# 共有ルームの設定（最初の1回）

アプリのコードとSQLは用意済みですが、実際の同期にはあなたのSupabaseプロジェクトが必要です。公開用キーだけで動作し、service_role/secretキーは使いません。

## 1. Supabaseにプロジェクトを作る

1. https://supabase.com/ でアカウントを作り、ダッシュボードの **New project** を選びます。
2. プロジェクト名を `MahjongScore` などにし、データベースのパスワードを設定します。このパスワードをアプリやGitHubに登録する必要はありません。
3. プロジェクトの作成完了を待ちます。

## 2. SQLで保存先・権限を作る

Supabaseの **SQL Editor → New query** を開き、このリポジトリの [schema.sql](schema.sql) の内容をすべて貼り付けて **Run** を押します。新しいプロジェクトで一度だけ実行してください。すでに同じテーブル・関数があるプロジェクトには重ねて実行しないでください。

SQLは共有ルームのテーブルと専用関数を作ります。テーブルのRLSを有効にし、直接の読み書きを禁止します。代表者の変更は認証済みの本人だけ、招待リンクによる読み込みは対応するルームだけに限定します。RLSを無効化する必要はありません。

## 3. 匿名サインインを有効にする

Supabaseの **Authentication → Sign In / Providers（または Providers）→ Anonymous Sign-Ins** を有効にします。

代表者はルーム作成時に自動で匿名サインインします。招待された人はサインイン不要で閲覧できます。編集権限は代表者のブラウザ内の認証情報で保持するため、別のブラウザ・別のスマホには引き継がれません。ブラウザデータの削除や匿名ユーザーの削除で編集権限を失います。メールログイン・権限の移譲・紛失後の回復は初期版では未対応です。

## 4. GitHubに公開用の接続設定を登録

Supabaseの **Connect** または **Project Settings → API / API Keys** から以下を確認します。

- **Project URL**（`https://<プロジェクトID>.supabase.co`）
- **Publishable key**（`sb_publishable_...`）または従来の **anon public key**

GitHubの `MahjongScore` リポジトリで **Settings → Secrets and variables → Actions → Variables** を開き、**New repository variable** で次の2つを追加します。

| Name                            | Value                                  |
| ------------------------------- | -------------------------------------- |
| `VITE_SUPABASE_URL`             | Project URL                            |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable key または anon public key |

これはブラウザへ配布する公開用の設定です。**service_roleキー、`sb_secret_...`、データベースのパスワードは登録しないでください。** キーの値をチャットに送る必要はありません。

この変更のPRをマージしてください。すでにマージ済みの場合は **Actions → Test and deploy GitHub Pages → Run workflow → main** で再ビルド・公開します。変数を変更するだけでは公開済みアプリに反映されません。

## 5. スマホでルームを作って共有

1. 公開アプリを開き、普段どおりプレイヤーとルールを設定します。
2. **共有ルームを作成 → 現在の記録をコピーして作成** を押します。確認画面に表示された全半荘の記録をコピーします。端末内の元データは残ります。
3. **招待リンクをコピー** してLINEなどで送ります。
4. 相手は招待リンクを開き、同じルームの成績・履歴を閲覧できます。代表者のみ入力・修正・削除・設定変更が可能です。
5. 更新は約15秒ごとです。**今すぐ更新** でも取得できます。旧招待リンクを無効にするには **招待リンクを再発行** を使います。

招待リンクを知っている人はルーム内の設定・全対局履歴を閲覧できます。再発行は今後の読み込みを拒否するもので、すでに相手が読んだ内容や出力したCSVを削除するものではありません。

**端末の記録に戻る** を押すと元のローカルデータを表示します。共有ルームへの変更は元のローカルデータに自動で書き戻しません。共有ルームの作成と別ルームの作成は独立し、招待リンクから再入室できます。代表者も編集時は作成時と同じブラウザで招待リンクを開いてください。

## 通信失敗・同時編集について

- 共有ルームはオンラインでの読み書きが必要です。取得失敗時は最後に読み込んだ内容を画面に残し、書き込みを停止します。再読み込み後のオフライン共有データ復元や未送信の変更キューはありません。
- 通信失敗時の保存は成功と表示しません。通信を回復して最新の内容を確認してください。
- 同じ代表者が複数タブで編集した場合は、保存時のバージョンを確認し、古い画面からの上書きを拒否します。「他の画面で記録が更新されました」と表示されたらフォームを閉じて更新し、入力し直してください。
- 1ルームのデータは最大1MB、対局は2,000半荘、登録メンバーは100人までです。長期利用ではCSVで保存し、新しいルームを作ってください。既存のローカルデータを自動で削除する処理はありません。

## 開発環境で試す

`.env.example` を `.env.local` にコピーし、同じ2つの公開用設定を記入して `npm run dev` を起動します。`.env.local` はGitに含まれません。クラウドで実際のSupabaseに接続する場合は、環境設定にも2つの変数を登録し、プロジェクトの `<プロジェクトID>.supabase.co` を接続先として許可してください。

```sh
npm test
npm run build
npm run test:e2e
npm run test:sync:e2e
```

通常のブラウザテストは公開用ビルドを使います。同期のブラウザテストはHTTP応答を模擬する専用ビルド `dist-sync-test/` と別ブラウザを使い、代表者・閲覧者、競合・通信失敗、ローカルデータの保持を確認します。**dist-sync-testを公開しないでください。** SQLの権限・招待トークン・競合検証はPGlite（PostgreSQLエンジン）で `schema.sql` を実行するテストです。Supabase本番の認証・実通信の確認はプロジェクト設定後に行ってください。
