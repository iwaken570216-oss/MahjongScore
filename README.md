# 雀録 — MahjongScore

スマートフォン向けの4人麻雀スコア管理PWA。黒とゴールドのUIで、半荘の素点・チップ入力、当日の成績、履歴編集・削除、CSV出力を利用できます。サーバーやアカウントは不要です。

## 開発・テスト

Node.js 22以上とnpmを使用します。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

開発サーバーはポート5173（`http://localhost:5173/MahjongScore/`）、ビルドのプレビューは4173（`http://localhost:4173/MahjongScore/`）です。npmキャッシュに書き込めないクラウド環境では `npm ci --cache /tmp/mahjong-npm-cache` を使用してください。アプリは通常のブラウザでも動作します。PWAとオフライン動作は本番ビルドで確認してください。

## 使い方

1. 「設定」で4人以上の名前、持ち点・返し点、ウマ、同点処理、1枚あたりのチップポイントを保存します。
2. 「今日」から今回参加する4人を東・南・西・北の席に選び、半荘終了時の点数を入力します。5人以上なら休む人が表示されます。初期値は全員0、箱下は負数で入力できます。
3. 点数合計は持ち点×4と一致させてください。残った供託はプレイヤーの点数に加算して精算してください。
4. チップは受け取りを正数、支払いを負数で入力します。合計0枚が必要です。
5. 「履歴」で日付検索・修正・削除、全期間のCSV出力ができます。過去の対局修正には、保存時の名前とルールを使います。

### 計算ルール

- スコア =（終了点数 − 返し点）÷ 1,000 ＋ 順位ウマ ＋ トップのオカ。
- オカ =（返し点 − 持ち点）× 4 ÷ 1,000。ウマは合計0に設定します。
- デフォルトは25,000点持ち・30,000点返し、ウマ20 / 10 / −10 / −20、オカ20。
- 同点均等分配では同順位（1・1・3・4など）として、占める順位のウマとオカを分配します。トップ率も同点人数で分配します。席順優先では登録順（東→南→西→北）で決めます。
- 累計順位はスコア順で、同スコアは同順位です。チップポイントは麻雀スコアに合算せず、累計順位は麻雀スコアのみで判定します。初期値は1枚=1ポイントです。
- スコアは小数第3位まで。日付は端末の現地日付を使い、指定した対局日ごとに集計します。
- 名前の変更は同じプレイヤーIDの表示名変更です。別のメンバーは「プレイヤーを追加」で登録してください。各人のIDごとに集計し、休んだ半荘は回数・トップ率の分母に含めません。登録から外しても過去の記録は残ります。過去の記録内の名前は変更しません。

## 5人以上で交代する場合

設定で5人以上を登録し、各半荘の入力画面で参加者4人を選びます。次の半荘では休みの人を参加者に選び、交代する人を外してください。同じ人を2席には選べません。次の入力では前回の参加者・席順を引き継ぎます。

当日の成績には登録メンバー全員を表示します。未参加者の順位は「—」、回数は0で、参加済みの人の順位に影響しません。半荘順位は参加した4人の素点で決めます。過去の履歴修正は保存時の参加者・ルールを使います。

### 旧金額形式のデータ

旧バージョンの対局・チップ枚数・参加者IDは書き換えません。旧金額はポイントに自動変換せず「旧記録」として別表示し、CSVにも専用列で残します。設定の旧単価は新しいポイント単価に流用せず、初期値1ptに移行します。新しい対局からチップポイントを計算します。

## コード構成

```text
src/domain/score.ts       型・順位・点数計算・累計（画面やDBに依存しない）
src/domain/csv.ts         CSV生成と数式注入対策
src/storage/db.ts         IndexedDBの読み書き
src/App.tsx               画面と入力・保存処理
src/style.css             スマホ対応の配色とレイアウト
public/manifest.webmanifest  ホーム画面追加用設定
public/sw.js              本番のオフラインキャッシュ
```

ブラウザの一連の操作とオフライン動作も自動検証できます。

```sh
npx playwright install chromium
npm run build
npm run test:e2e
```

既存のChromiumを使うクラウド環境では `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e` を実行します。テストはChromiumでiPhone / Android相当の画面サイズを使い、設定・箱下入力・保存・再読み込み・修正・CSV・削除・オフライン保存を検証します。iOS Safari / Android実機でのホーム画面追加は別途確認してください。

`npm run format` でコードを整形できます。

計算ロジックの変更は `score.ts` と対応するテストから始めてください。テストでは通常計算、箱下、同点・席順、変更ルール、トップ率、CSV、IndexedDBの保存・修正・削除を検証しています。

## GitHub Pagesへの公開方法

このリポジトリは `vite.config.ts` の `base: "/MahjongScore/"` により、GitHub Pagesのリポジトリ配下で動作します。JavaScript・CSS・manifest・Apple用アイコン・Service Workerはこの配下から読み込まれます。manifest内の起動URLとアイコンはmanifest自身を基準にした相対パスです。

`.github/workflows/pages.yml` が自動ビルド・デプロイを行います。プルリクエストではテストとビルドだけを実行し、`main` へのpush（PRのマージを含む）ではテスト成功後に `dist/` をGitHub Pagesへ公開します。外部サービスのトークンや手動の `gh-pages` ブランチは不要です。

### GitHubで最初に行う操作

1. リポジトリの **Settings → Pages** を開きます。
2. **Build and deployment → Source** を **GitHub Actions** にします。
3. この変更のプルリクエストを開き、チェック成功後に **Merge pull request** で `main` にマージします。
4. **Actions** の **Test and deploy GitHub Pages** が成功するまで待ちます。
5. `https://iwaken570216-oss.github.io/MahjongScore/` を開きます。初回は公開反映まで数分かかることがあります。

マージ前にPagesのSourceを設定しておくと、最初のマージで公開できます。設定を後から行った場合は、Actionsで同ワークフローを選び **Run workflow → main** を実行します。失敗した場合はActionsの赤いジョブを開き、失敗したステップを確認してください。

GitHubリポジトリの設定でActionsが無効化されている場合は有効化してください。組織の制限がある場合は管理者による許可が必要になることがあります。

### configure-pagesで「HttpError: Not Found」が出た場合

このワークフローはViteの固定baseでビルドした成果物を `actions/deploy-pages@v4` で直接公開します。Pagesのメタデータによるビルド設定が不要なので、`actions/configure-pages` は使用しません。

Pagesは **Settings → Pages → Source: GitHub Actions** で事前に有効化してください。`configure-pages` の `enablement: true` は通常の `GITHUB_TOKEN` ではPagesを新規有効化できず、別の権限付きトークンが必要になるため、この構成では使用しません。deployジョブには `contents: read`、`pages: write`、`id-token: write` を明示しています。追加のシークレットは不要です。

修正PRをmainにマージすると、新しいワークフローが自動実行されます。古い失敗実行の「Re-run jobs」は古いコミットのワークフローを再実行するため、修正確認には使わないでください。必要なら **Actions → Test and deploy GitHub Pages → Run workflow → main** から新しい実行を開始します。

直接デプロイでも404が出る場合は、PagesのSourceがGitHub Actionsであることと、対象リポジトリでPagesが有効になっていることを再確認してください。403が出る場合はActionsのログのGITHUB_TOKEN権限と、組織・リポジトリのActions制限を確認してください。`github-pages` Environmentに承認待ちが表示された場合は、その承認を完了します。

### 保存データについて

IndexedDBのDB名・保存形式・読み書きの実装は維持しています。公開後も同じ端末・ブラウザ・公開URLでの再読み込みやアプリ更新後に記録を利用できます。ただし保存領域はオリジン（ドメイン・プロトコル・ポート）ごとに分かれるため、localhostやクラウドプレビューに保存したデータはGitHub Pagesに自動移行されません。公開前に必要な記録をCSVで出力してください（CSVからの復元は未対応です）。

### 他のホスティングへの配置

`npm run build` で生成される `dist/` をHTTPSの静的ホスティングに配置します。ドメインのルートに配置する場合は `npm run build -- --base=/` でビルドしてください。標準ビルドは `/MahjongScore/` 配下への公開用です。サーバー側APIや環境変数は不要です。

更新公開時には `public/sw.js` の `CACHE` バージョンを上げてビルドしてください。新しいService Workerは開いているアプリをすべて閉じた後に有効になります。初回にオンラインで読み込み、Service Workerの準備が完了すると再訪時にオフラインでも使えます。

- iPhone: Safariの共有メニュー →「ホーム画面に追加」
- Android: Chromeなどのメニュー →「アプリをインストール」または「ホーム画面に追加」

アイコンは一索（イーソウ）の扇状の尾を広げたクジャクをモチーフにした192px / 512pxのPNGです。iPhoneのホーム画面用には180pxのPNGを指定しています。実機でのインストール操作はブラウザ・OSにより異なります。

## データの注意点

端末のブラウザ内のIndexedDBに保存します。別端末や別ブラウザへの同期、CSVからの復元は未対応です。ブラウザデータの削除、プライベートブラウジング、ストレージの自動消去で失われる可能性があります。定期的にCSVを出力してください。CSVはBOM付きUTF-8で、Excel向けの引用符処理と名前の数式注入対策を行っています。スコアとチップポイントと旧金額は別列です。
